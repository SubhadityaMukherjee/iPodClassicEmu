# AGENTS.md — iPodClassic contributor/agent guide

Native iOS (SwiftUI + AVFoundation/MusicKit/PhotoKit) iPod Classic emulator: full-device UI on a black body with a real click wheel (CoreHaptics + tick sounds), LCD screen with subtle CRT scanlines, and classic iPod menus.

## Commands

```sh
xcodegen generate                      # regenerate iPodClassic.xcodeproj from project.yml (after adding files)
xcodebuild -project iPodClassic.xcodeproj -scheme iPodClassic \
  -destination 'platform=iOS Simulator,name=iPhone 17' build   # verification build
xcodebuild -project iPodClassic.xcodeproj -scheme iPodClassic \
  -destination 'platform=iOS Simulator,name=iPhone 17' test     # unit tests
```

There is no linter; keep style consistent with surrounding code. Swift 5, iOS 18 deployment target, `SWIFT_STRICT_CONCURRENCY: minimal`.

## Architecture

- `project.yml` is the source of truth for the Xcode project; the `.xcodeproj` is generated and committed. Bundle: `com.ipodclassic.app`; the signing team is configured once via `DEVELOPMENT_TEAM` in `project.yml` (never hardcode team IDs in docs).
- `Sources/App/` — `iPodClassicApp` (@main), `AppModel` (`@Observable`; nav `stack: [Route]`, input router `handle(ControlEvent)`, service singletons), `AppSettings` (`ObservableObject`, UserDefaults-backed). `ControlEvent`/`Route` live in AppModel.swift.
- `Sources/Device/` — `DeviceView` (body layout, Hold switch, dim/sleep overlays, alarm ringer host), `ScreenView` (LCD + title bar), `CRTOverlay`, `ScreenRouter` (renders the nav stack; deep routes stay alive so state survives pops; top route owns wheel input; `title(for:)` maps routes to title-bar strings). The wheel floats in the lower body (wheel 0.66×width; the leftover space below the LCD splits 0.55 above / 0.45 below → wheel center ≈ 71% of screen height). Idle dim covers ONLY the LCD (0.62 black inside the screen clip) — the wheel and body never dim (user request 2026-11-08; the old detached-lighting/Backlight Illusion was removed).
- `Sources/Wheel/` — `ClickWheelView` + `WheelCoordinator` (angle-delta ticks at 15°/detent, adaptive scrolling: smoothed angular speed scales rows per detent 1→6 via `rowsPerDetent(speed:)` with `WheelFeedback` throttling pulses to 50/s so fast spins don't saturate haptics, button quadrants vs diagonal scroll sectors, press→scroll conversion, hold timers with repeat), `WheelHaptics` (CoreHaptics transients + UIImpact), `TickSounds` (AudioServices; never touches AVAudioSession), `WheelFeedback` (applies haptics/sound settings). The wheel face draws subtle dark-grey diagonal seams between the four button sectors (no press highlight).
- `Sources/UI/` — `Theme` (colors/fonts: LCD paper, brushed-metal bar, blue selection gradient, dimmed wheel), `MenuComponents` (`MenuItem`, `MenuList`/`MenuRow` incl. thumbnails + subtitles, `SplitMenuLayout`, `ModalPanel`, `moveListSelection` honoring Infinite Tick / Rubber Band Tick).
- `Sources/Features/` one folder per feature, each self-contained (model + screens):
  - `Music/` — MusicKit library fetch (cached in `MusicService`), `PlayerModel` (ApplicationMusicPlayer, transport, queue bookkeeping synced from `player.queue.currentEntry`, volume, 0.5s state polling), list screens (hold center on a song row = queue options panel: Play Next = right after the current track, Add to Queue = end of Up Next; shared `SongHoldState`), `AlbumDetailScreen` (View in Cover Flow / Shuffle / tracks), `ArtistDetailScreen` (Play All / Shuffle All / **Search** rows + albums — Search pushes `.artistSearch` → `ArtistSearchScreen`: touch keyboard + wheel results ranked title-prefix > title-contains > album, scoped to that artist's songs; QA hook `START_ROUTE=artistSearch`), `CoverFlowScreen` (3D covers + numbered track overlay), `NowPlayingScreen` (artwork with classic fading reflection + QA fake cover under FAKE_LIBRARY; wheel = volume; hold center = song options incl. Up Next queue list with jump-to-entry and an AirPlay route-picker row).
  - `Extras/` (in `Features/Extras/ExtrasScreens.swift`) — Extras menu, Flashlight (torch), Calendar, `MusicSearchScreen` (ranked song search; hold center → Go to Artist / Go to Album).
  - `Photos/` — `PhotoLibraryModel` (PHFetchResult + thumbnail cache), grid/detail screens.
  - `Camera/` — `CameraModel` (AVCaptureSession on serial queue, zoom, lens switch, capture delegate), `CameraScreen` (wheel zoom, prev/next = aspect ratio, hold = flip lens RATE-LIMITED to one flip per hold because `.prevHold`/`.nextHold` repeat every ~0.18s — the repeat toggled the lens back and forth, center = capture, MENU = options panel; claims transport buttons via `model.transportClaimedByScreen`).
  - `Recorder/` — `RecorderModel` (.m4a in Documents/Recordings, pause/resume, background-safe, interruption handling, playback; recording session = `.playAndRecord` with `[.defaultToSpeaker, .allowBluetoothHFP]` — the `.allowBluetoothHFP` option is REQUIRED or AirPods disconnect mid-recording: without it iOS engages the BT mic, finds no declared BT support, and churns A2DP↔HFP; with it AirPods make one clean switch at record start, mic + monitoring through the AirPods, `.defaultToSpeaker` remains the no-BT fallback), recorder/list/detail screens with share sheet. TRANSCRIPTION (`Transcription.swift`, on-device STT): NVIDIA Parakeet **Ultra** CoreML via the FluidAudio SPM package v0.18.3 (multilingual 25 EU languages, punctuation+cases, ANE; ~600 MB download from HuggingFace handled by the SDK on first use — `ensureModels()` surfaces download state; first DEVICE load compiles for ANE and takes ~10 minutes, cached after; the sherpa-onnx/onnx 0.6b and 110m paths were tried and REMOVED — the 0.6b ORT build dequantizes to ~2.4GB and JETSAMS on device, and v3-coreml mangles Dutch on iOS while Ultra decodes it perfectly); transcription runs URL-based with the SDK's disk-backed chunking (~1.2MB constant memory — hour-long memos are safe), progress streams from the SDK into the transcription Live Activity; transcript JSON sidecar `Documents/Recordings/.transcripts.json` (state done/partial/failed, saved before+after each run so a kill never loses state), retry failed from the hold menu, View Transcript screen (wheel scrolls via TextViewProbe re-resolution; hold center = Transcript Options panel: Share / Cancel — Share hands the CLEAN TEXT to the share sheet, not a file; transcripts are paragraph-formatted by `TranscriptStore.formatParagraphs` — ICU sentence split grouped 5 sentences/line, idempotent, applied at save + display + share + Shortcuts output), deletion removes the sidecar entry; `downloadState` is initialized from a disk-cache probe (`AsrModels.modelsExist`) so a cached model never shows "Downloading" — a cached load keeps state .ready and is silent, only a real download mirrors to the Live Activity and the download panel; SilentKeepAlive (silent AVAudioPlayer loop) keeps the audio session alive in background; App Intents `TranscribeRecordingIntent` / `GetTranscriptionIntent` (Shortcuts: recording entity query over Documents/Recordings); one-time sweep removes sherpa-era model dirs and QA artifacts; QA: `QA_TRANSCRIBE=<file in Documents/Recordings>` runs model-load+transcribe end-to-end, writes stage status to `Documents/qa_status.txt`, and logs `RESULT ... rtf= headroomMB=` on category "transcribe", `START_ROUTE=transcript` opens the QA transcript screen.
  - `Notes/` — `NotesStore` (.txt in Documents/Notes, visible in Files app), list + editor (touch keyboard, debounced autosave, MENU writes; wheel scrolls the note via a probe anchor that RE-RESOLVES the backing UITextView each scroll when the cached one detaches — SwiftUI recreates the text view across keyboard/background transitions and a one-shot capture silently killed scrolling; Done capsule / center dismisses the keyboard; hold center = Note Options panel: Font Size (wheel adjusts live, center saves, MENU cancels; persisted `notes.fontSize`) / Share / Cancel; list hold menu = Share / Delete / Cancel).
  - `Clocks/` — `AlarmStore` (single classic alarm with weekday repeats; nothing selected = daily → one repeating `UNCalendarNotificationTrigger` per selected day), `AlarmNotifications` (delegate → in-app ringer), `TimerModel`/`StopwatchModel`, `RingerManager` (in-app loop + overlay), `AlarmScreen` (wheel edits hour/minute/AM-PM, day cursor; center advances/toggles — wheel past the day-row edges changes segment), `TimerScreen`, `StopwatchScreen`.
  - `Reader/` — PDF/EPUB reader. `ReaderStore` (registry in Documents/Books + per-book settings/position persisted in UserDefaults; new books default `scrollStep = 0` = 1 page per wheel tick — the old default 2 ("Large", 3 pages/tick) made every freshly imported book "skip pages", healed by the `reader.newBookStepMigrated` one-time migration), `EpubContainer` (custom ZIP extractor over Apple `Compression` + OPF/spine/TOC parsing — chapter titles from toc.ncx/EPUB3 nav, then `<title>`/`<h1>`), `PDFReflow` (text PDFs reflow through the EPUB pipeline: Book setting View → "Reflowed" extracts text once into `<bookDir>/reflow/<i>.html` chapters from top-level outline spans (no outline = whole book), paragraph joiner breaks on sentence-terminal lines + de-hyphenates; image-only PDFs revert with a toast; reflow keeps its OWN position fields (`reflowChapter`/`reflowFraction`) so switching view modes never moves the page view; QA hook `READER_PDF_REFLOW=1`), `ReaderHighlights` (selection capture + persistent text-anchored marks + `- "text"` notes mirror; reflow highlights use the PDF store via the DOM path), `ReaderScreens` (`ReaderScreen` list w/ Files-app import + hold-to-delete, `BookScreen`: true column pagination — one tick = one page, pages hold complete lines only; center = chapters, hold center = book settings (font 11–25px + 6 font families/line spacing/margins/screen dim/PDF view mode Continuous/One Page/Reflowed), prev/next = chapter or page; tiny page readout "cur/total" right of the whole-book progress bar — same numbers as the bar fraction; progress = per-chapter page counts: chapters are ESTIMATED from stripped text length at current typography (0.44em glyph prior) and chapters the user visits get EXACT counts from `readerPosition` (scrollFraction now returns {f, n}) which recalibrate the whole book; NOTE: never re-add an offscreen WKWebView measurer — iOS WebKit paginates columns asynchronously, scrollWidth overshoots then tightens, and about:blank races made the old hidden measurer report every chapter as 1 page); position autosaves every 6s + on background; PDF highlights are native `PDFAnnotation`s written into the PDF file; injects `width=device-width` viewport — books without one lay out at 980px).
  - `Settings/` — value-cycling rows via `ValueSettingsScreen`; Apple Music connect, Clickwheel, Display (CRT/scanlines/dim), Playback, About.
- Input flow: `ClickWheelView` → `AppModel.handle` → (hold switch / sleep / global transport interception) → `controlBus` (Combine) → only the top screen reacts via `.onReceive`.
- Global transport: prev/next/play/pause always control music (like a real iPod) except when a screen claims them (camera). MENU-hold goes home; PLAY-hold sleeps.
- Live Activities: `iPodClassicWidgets` extension target (bundle `com.ipodclassic.app.widgets`) shows one activity per kind (timer/stopwatch/recorder) on lock screen + Dynamic Island. `Shared/TrackActivityAttributes.swift` is compiled into BOTH the app and the widget; `LiveActivityManager` (Sources/App) is driven by the timer/stopwatch/recorder models. All on-screen motion is auto-ticking `Text(timerInterval:)` — the app only posts updates on start/pause/resume/lap/end, no push token. Requires `NSSupportsLiveActivities` (set in project.yml); Dynamic Island needs a real device.

## Sounds & resources

- `Resources/Sounds/*.caf` — Tick/TickSoft/RubberBand/AlarmBeep; regenerate via python wave + `afconvert -f caff -d LEI16@44100 -c 1`. Alarm notification sound must stay < 30 s.
- `scripts/make_icon.swift` — regenerates the AppIcon PNG.
- Info.plist keys (Music, Camera, Mic, Photos, background audio) are generated from `project.yml`.

## Tests

- `Tests/iPodClassicTests/` — unit tests (no host app): `TimeFormat`, `WheelCoordinator` geometry + adaptive `rowsPerDetent` tiers, alarm hour24 + repeat labels/bitmask, `PlayerModel` volume, playback session codec (`PlaybackSessionStore`), notes wheel-scroll clamp + list ordering, route map + title-bar coverage, `moveListSelection` (clamps + Infinite Tick), timer/stopwatch state machines, reader font CSS + settings decode, `ReaderStore` import/remove/old-format decode + new-book 1-page tick default, ZIP extraction (stored + deflate + traversal guard), EPUB spine/TOC/title parsing, `HighlightStore`.
- `Tests/UITests/` — real-gesture E2E over XCUI (`WheelTapTests`, `E2ETests`, `NotesEditorTests`): wheel drag → tick, center tap, hold timers, navigation depth, alarm ringer fire/dismiss, reader render, songs hold, notes editor wheel-scroll + Done keyboard dismiss + wheel still scrolls after a keyboard cycle. Launch hooks via `launchEnvironment`: `RESET_DEFAULTS=1`, `START_ROUTE=<route>` (or `readerLast` = reopen last book; `noteEditor` opens the QA note), `FAKE_LIBRARY=1` (QA seed songs + fake Now Playing track + fake cover so the artwork reflection renders without a library — MusicKit items can't be constructed in tests), `DIM_AFTER=N` (forces the idle-dim threshold; the sim ignores `defaults write` into the app domain), `ALARM_ENABLE=1|0` (arm/disarm from any launch, not just the alarm screen), `ALARM_FIRE_SECONDS=N`, `AUTOPLAY=1` (shuffle-plays the real library at launch — device only, for real-music screenshots), notes harness: `START_ROUTE=noteEditor` + `NOTES_QA=1` (seeds a 60-line QA note and shows a tiny `y=<offset>` readout so tests can assert the UITextView actually scrolled) + `NOTES_PANEL=1` (opens the Note Options hold menu for screenshots), reader harness: `READER_IMPORT=<file>` / `READER_CHAPTER=<n>` (spine index) / `READER_FRACTION=<0…1>` (in-chapter position) / `READER_FONT=<idx>` (force a font family; visual font-setting checks) / `READER_TICKS=<n>` (stalls on junk front-matter pages — prefer CHAPTER+FRACTION) / `READER_DEBUG=1` (os_log GEOM line per page turn: innerWidth/clientWidth/scrollWidth/body rect — the layout probe for pagination bugs), panel shots: `NOW_PLAYING_PANEL=1` / `BOOK_SETTINGS=1`.
- README screenshots: music/menu shots come from the real iPhone via `devicectl device process launch --terminate-existing --environment-variables '{...}'` + `devicectl device capture screenshot` (needs the phone unlocked; AUTOPLAY for real artwork); content-dependent shots (photos, camera, reader, reader_settings, notes, recorder) come from the simulator. All get rounded with `swift scripts/round_corners.swift 56 <pngs>`. Camera shots MUST come from the simulator — device screenshots can't capture the live camera preview (always black). gotchas: launching over a running app silently DROPS the `SIMCTL_CHILD_*` env — always `simctl terminate` + `sleep 2` + plain `simctl launch`, and in zsh never pass envs through an unquoted variable or build env names by string interpolation (`SIMCTL_CHILD_$1` sets the wrong variable) — write each `SIMCTL_CHILD_X=...` inline. `simctl spawn defaults write` into the app's domain is unreliable on the iOS 26.5 sim (the app may not see the value, and `RESET_DEFAULTS` may not clear it) — a stale `display.dimAfter=2` once made every wheel UI test fail because the dim overlay ate the taps; use env hooks, and if a sim acts haunted, check `simctl spawn booted defaults read com.ipodclassic.app <key>`.

## Conventions & gotchas

- SwiftUI (iOS 17+): writing to a `@State` that `body` never reads does NOT invalidate the view. The old idle-dim heartbeat (`@State heartbeat` written by a 2 s timer but never read) silently never re-rendered — the dim overlay never appeared. Periodic re-renders go through the `@Observable` AppModel instead: `model.tickIdle()` updates the tracked `clockTick`, and anything time-dependent (`isDimmed` in DeviceView/HoldSwitchView) reads it.
- Screens consume `ControlEvent` in `.onReceive(model.controlBus)` and call `moveListSelection` for lists — never reach into other screens' state.
- New screens need: a `Route` case, a `ScreenRouter` entry, and a `title(for:)` branch.
- Music playback requires a real device (ApplicationMusicPlayer is a simulator no-op) and MusicKit working via Xcode automatic signing; camera needs a physical device too.
- `AppSettings` is `ObservableObject` (not `@Observable`) with explicit `objectWillChange.send()` in setters — UserDefaults-backed computed properties don't auto-notify otherwise.
- Battery icon reads `UIDevice.current.batteryLevel` (enabled at app init; -1 in sim → 100%).
- Git flow: feature branches → commit → push → merge to `main`. Short imperative subjects.
- MusicKit queue sync: queue entries are transient on insertion — entry IDs are temporary, entries get replaced when the playback engine resolves them, and `Entry.item` can be nil mid-resolution. NEVER map bookkeeping by entry ID/item snapshot; match `player.queue.currentEntry.title` (+ `subtitle` = artist) against your own song array in the poll tick. Transport uses `skipToNextEntry`/`skipToPreviousEntry` (throws harmlessly at queue end). The queue is an `ObservableObject` but its events are not settled at event time — poll, don't trust the event.
- `ApplicationMusicPlayer` plays in-process: background audio requires an active `AVAudioSession` `.playback` category, activated once at app launch. The alarm ringer must never deactivate the session, and the keep-alive timer must not reconfigure it while music plays — that was the music-dies-in-background bug.
- PDFKit (this SDK): `PDFDocument` has no `.pages` — use `pageCount`/`page(at:)`/`index(for:)`; `PDFOutline` iterates via `numberOfChildren` + `child(at:)`.
- More MusicKit quirks (this SDK): `ApplicationMusicPlayer.Queue.Entry.id` is a plain `String` (not a `MusicItemID`); `Song.duration` is `TimeInterval?` — coalesce before math.
- Playback persistence: the session (queue song IDs in play order, index, position) is saved to UserDefaults on background/terminate, on track change, and every ~2 s while playing (`PlaybackSessionStore`); at launch `AppModel` re-fetches the songs by ID (`MusicService.songs(withIDs:)`) and arms `PlayerModel.restore(...)` PAUSED — never auto-play. QA envs `AUTOPLAY=1` / `FAKE_LIBRARY=1` skip restore. `MusicService.loadLibrary` fetches its four sections concurrently and publishes all four arrays at once (single re-render wave; no mixed-state window where albums are filled but songs still empty).
- Swift/JS escaping: `\\(x)` inside a Swift string emits the literal text `\(x)` — interpolation does NOT happen. In JS source strings passed to `evaluateJavaScript`, interpolate with single-backslash `\(x)` and verify with a standalone `swift` script before shipping (this silently shipped invalid reader CSS once).
